<p align="center">

## О программе

«Хранилка» — настольное Windows-приложение для хранения расширенной информации
об учётных записях: не только логин и пароль, но и всё, что обычно теряется по
заметкам и скриншотам:

- логины, пароли, URL;
- секретные вопросы и ответы;
- фразы восстановления и одноразовые коды;
- персональные данные, указанные при регистрации;
- метаданные регистрации (IP, браузер, ОС);
- заметки и произвольная дополнительная информация;
- **галерея изображений** (чеки, инвойсы, скриншоты) — хранится внутри документа;
- связи между аккаунтами («этот аккаунт привязан к этой почте»).

Документ также может содержать финансовые инструменты: банковские карты и
криптокошельки. Они хранятся в той же базе, могут быть привязаны к аккаунтам и
сервисам либо оставлены свободными.

Весь документ — один файл `hranilka.db` рядом с программой. Резервная копия —
это копия одного файла, включая все изображения.

## Возможности

**Организация**
- Дерево «папки → сервисы → аккаунты» с поиском и избранным.
- Карты и криптокошельки — листья того же дерева: их можно создать в сервисе
  или отдельно, переместить, добавить в избранное и восстановить из корзины.
- Ручная сортировка перетаскиванием либо сортировка по имени, дате создания,
  сроку смены пароля.
- Напоминание о смене пароля: задайте интервал — просроченные аккаунты
  помечаются `[!]`.
- Корзина (опционально): удалённые аккаунты, карты и криптокошельки можно
  восстановить.
- Несохранённые правки не теряются при переключении карточек — черновики
  помечаются в дереве маркером «● НЕ СОХРАНЕНО».

**Финансовые инструменты**
- Банковские карты: реквизиты, срок действия, CVV/PIN, данные держателя,
  банковские и счётные реквизиты, заметки и галерея документов.
- Криптокошельки: тип/устройство, seed-фраза и passphrase, адреса сетей,
  приватные ключи, заметки и галерея документов.
- Связь «аккаунт ↔ финансовый инструмент» двусторонняя: с карточки аккаунта
  можно перейти к привязанной карте/кошельку и обратно.
- Показ финансовых инструментов можно отключить в настройках: записи останутся
  в базе и корзине, но скроются из дерева, связей, создания и экспорта.
- Изображения в аккаунтных и финансовых галереях ограничены 15 МБ на файл,
  50 файлами на запись и общим объёмом 500 МБ на базу.

**Шифрование (опционально)**
- Мастер-пароль шифрует весь документ: AES-256-GCM, ключ из пароля через
  Argon2id (три пресета стойкости — от «быстро» до «параноик»).
- Конвертная схема: смена мастер-пароля мгновенна, без перешифровки всей базы.
- Recovery-код (160 бит энтропии) — независимый способ открыть базу при утере
  пароля; показывается один раз при включении шифрования.
- Подделка или повреждение зашифрованного файла обнаруживаются
  криптографически (GCM-аутентификация).

**Защита во время работы**
- Автоблокировка по простою (для зашифрованной базы — с повторным вводом
  мастер-пароля).
- Автоочистка буфера обмена через заданное время после копирования пароля.
- Защита от скриншотов и захвата экрана (Windows, `WDA_EXCLUDEFROMCAPTURE`).
- Затирание удалённых данных внутри файла базы (`secure_delete`), атомарная
  запись на диск, защита от повторного запуска.

**Инструменты**
- Генератор паролей и генератор персональных данных (РУ/США).
- Экспорт в TXT, CSV, XLSX и HTML — всего дерева или отдельной ветки, с
  выбором состава полей и защитой от CSV-инъекций. В XLSX аккаунты и финансовые
  инструменты выводятся отдельными таблицами на одном листе.
- Настраиваемые горячие клавиши (включая кириллическую раскладку).

**Внешний вид «под 2000-е»**
- 8 предустановленных тем: MS-DOS, Windows 95, Matrix, Amber Monitor,
  Green Terminal, Blue Screen, Cyberpunk, Classic IDE.
- Любую тему можно доработать: шрифт, размер текста, цвет текста и фонов
  настраиваются независимо и применяются ко всему интерфейсу.

**Отзывчивость**
- Асинхронная архитектура (qasync): чтение и запись базы, шифрование и
  загрузка изображений идут в фоне — интерфейс не замирает даже на базе в
  сотни мегабайт.

## Безопасность: что важно знать

> **По умолчанию шифрование ВЫКЛЮЧЕНО.** Пока вы не включили мастер-пароль в
> настройках, `hranilka.db` — обычный незашифрованный файл SQLite: любой, кто
> получит доступ к файлу, прочитает все данные. Это осознанный выбор в пользу
> простоты («замена блокнота»), но для реальных секретов **включите шифрование**
> в «Настройки → Шифрование».

Также учтите:

- **Бэкапы наследуют режим базы.** Бэкап незашифрованной базы — незашифрованная
  копия всех данных. Включайте шифрование до настройки авто-бэкапов в облачные
  папки.
- **Экспорт всегда открытым текстом.** Выбранные данные аккаунтов попадают в
  TXT/CSV/XLSX/HTML без шифрования. У финансовых инструментов CVV, PIN,
  seed-фразы и приватные ключи по умолчанию исключены, а номер карты маскируется;
  их полное раскрытие требует отдельного выбора. Храните и удаляйте экспорт
  осознанно.
- **Recovery-код равен мастер-паролю по силе доступа.** Храните его отдельно
  от компьютера.
- Служебные файлы `*.pre-restore`, `*.pre-migrate-*`, `*.rollback`, `*.recovery`,
  `*.locked-*` — это полные копии базы, создаваемые для страховки при
  восстановлении и миграции. Не публикуйте их и не выкладывайте вместе с
  исходниками (все шаблоны уже внесены в `.gitignore`).

## Быстрый старт

Требуется Python 3.13+ (Windows).

```powershell
git clone <url-репозитория>
cd Hranilka
python -m venv venv
./venv/Scripts/python.exe -m pip install -r requirements.txt
./venv/Scripts/python.exe main.py
```

При первом запуске рядом с программой создаются `hranilka.db` (документ) и
`config.json` (настройки). Программа переносима: папку можно скопировать
целиком вместе с данными.

## Сборка автономного .exe

Версия PyInstaller закреплена в `requirements-dev.txt` для воспроизводимости.

```powershell
./venv/Scripts/python.exe -m pip install -r requirements-dev.txt
Remove-Item -Recurse -Force build, dist -ErrorAction SilentlyContinue
./venv/Scripts/python.exe -m PyInstaller Hranilka.spec
# готовый файл: dist/Hranilka.exe
```

## Резервное копирование и восстановление

- **Бэкап** («Настройки → Бэкапы»): копия всего документа одним файлом с
  ротацией по количеству; можно включить авто-бэкап при закрытии программы.
- **Восстановление**: кандидат проверяется (структура, `quick_check`,
  `foreign_key_check`, версия схемы) **до** замены рабочей базы. Перед заменой
  создаётся страховочная копия; если восстановленный файл не открылся, не
  прошёл аутентификацию (шифрование) или проверку схемы — рабочая база
  возвращается автоматически.
- **Миграция схемы**: при открытии базы от прежней версии программы сначала
  создаётся страховочная копия с уникальным именем
  (`*.pre-migrate-v{версия}-{дата}`); при сбое миграции копия остаётся на диске
  и никогда не перезаписывается последующими запусками. Если копию создать не
  удалось — миграция не начинается.

## Тесты

```powershell
./venv/Scripts/python.exe -m pip install -r requirements-dev.txt
./venv/Scripts/python.exe -m pytest
```

Сюита — 413 тестов (крипто-контейнер, миграции, бэкап/восстановление,
конкурентность, галерея, финансовые инструменты, экспорт, UI-смоук) — выполняется headless
(`QT_QPA_PLATFORM=offscreen`) и не трогает вашу базу. Типизация слоя данных
проверяется строгим mypy: `./venv/Scripts/python.exe -m mypy`.

## Технологии

| Компонент | Что используется |
|---|---|
| GUI | PySide6 (Qt 6), кастомное frameless-окно |
| Хранилище | SQLite (один файл, изображения — BLOB) |
| Шифрование | cryptography (AES-256-GCM), argon2-cffi (Argon2id) |
| Асинхронность | qasync + фоновые потоки записи |
| Экспорт | openpyxl (XLSX), собственные TXT/CSV/HTML |

## Структура проекта

```
main.py                    — тонкая точка входа (python main.py / PyInstaller)
hranilka/                  — код приложения (__version__ — версия релиза)
├── app.py                 — bootstrap: QApplication + qasync-цикл
├── core/                  — конфиг, пути, утилиты, доменные правила, хоткеи,
│                            типы и правила финансовых инструментов
├── crypto/store.py        — конвертное шифрование (Argon2id + AES-256-GCM)
├── data/                  — слой данных (Qt-free)
│   ├── database/          — Database: CRUD аккаунтов/финансов, concurrency,
│   │                        persistence и schema
│   │   └── migrations/    — нумерованные миграции схемы (runner + реестр)
│   ├── errors/            — исключения слоя данных (файл на класс)
│   └── models/            — модели аккаунта и финансовой записи
├── services/              — прикладные сервисы над данными
│   ├── backup.py          — бэкапы с ротацией и проверяемое восстановление
│   └── export.py          — экспорт TXT/CSV/XLSX/HTML
├── generators/            — генерация паролей, парольных фраз, ПД
└── ui/                    — интерфейс и темизация
    ├── main_window.py     — MainWindow, vault_controller.py — фоновая запись
    ├── widgets/           — поля карточек, галерея, коды 2FA, seed-фразы
    └── dialogs/           — настройки, разблокировка, экспорт, корзина
tests/                     — pytest-сюита
```
