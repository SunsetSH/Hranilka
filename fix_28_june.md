## Баг 1
Незашифрованная база данных не восстанавливается из бекапа  с ошибкой win error 5

Мнение программиста и как исправить:
Причина найдена: активное SQLite-соединение держит hranilka.db открытым.

  Последовательность:

  1. dialogs.py:995 вызывает restore_backup().
  2. backup.py:147 выполняет:

     os.replace(tmp, dst)

  3. Но plaintext-база открыта через sqlite3.connect(self.db_path) в database.py:76.
  4. На Windows открытый SQLite-файл нельзя заменить через os.replace, поэтому возникает WinError 5.
  5. _reload_database() закрывает соединение только после успешного восстановления (main.py:586), то есть слишком
     поздно.

  run_exclusive() останавливает фоновый writer, но SQLite-соединение не закрывает.

  Это зависит не столько от типа backup, сколько от текущего режима: при зашифрованной текущей базе SQLite работает
  в :memory:, поэтому файл на диске не занят.

  Исправление: перед restore_backup() закрыть текущую БД без сохранения, выполнить замену и затем обязательно открыть БД
  заново — также при ошибке:

  self.db.close(persist=False)
  try:
      bk.restore_backup(path, self.db.db_path)
  finally:
      self._open_database(self)

  Лучше перенести всю операцию восстановления из SettingsDialog в MainWindow, чтобы один метод атомарно управлял
  последовательностью:

  остановить writer → закрыть SQLite → restore → открыть БД → обновить UI

  Дополнительно опасен backup.py:150: при ошибке он делает shutil.copy2(rollback, dst) поверх всё ещё открытой SQLite-
  базы. Это также нужно выполнять только после закрытия соединения.

## Баг 2
Размер файла hranilka.db не уменьшается, а  может только увеличиваться
Мнение программиста и как исправить:
Картинки из таблицы удаляются. Размер файла не уменьшается из-за поведения SQLite.

  Путь удаления:

  - UI удаляет элемент из self.items: widgets.py:619-628;
  - при нажатии «Сохранить» выполняется database.py:1250:

    DELETE FROM gallery WHERE account_id = ?

  - затем заново записываются только оставшиеся изображения.

  SQLite после DELETE не уменьшает файл. Освободившиеся страницы попадают во внутренний freelist. Поэтому:

  - после удаления размер файла прежний;
  - повторное добавление картинки использует свободные страницы;
  - размер также не растёт.

  Последний пункт фактически подтверждает, что место было освобождено и повторно использовано.

  Важно: без нажатия «Сохранить» удаление остаётся только в интерфейсе.

  Проверить можно запросами:

  SELECT COUNT(*), SUM(LENGTH(image_data)) FROM gallery;
  PRAGMA page_count;
  PRAGMA freelist_count;

  После удаления количество строк и сумма BLOB уменьшатся, а freelist_count увеличится.

  Для физического уменьшения файла нужен:

  VACUUM;

  Его нельзя запускать после каждого удаления: он блокирует БД, переписывает её целиком и требует дополнительного места.
  Лучше добавить отдельную команду «Сжать базу» через VaultController.run_exclusive().

  Для plaintext-режима также стоит включить:

  PRAGMA secure_delete = ON;

  Это перезаписывает содержимое удалённых страниц, но не уменьшает файл. VACUUM одновременно удалит свободные страницы и
  сократит размер базы.
